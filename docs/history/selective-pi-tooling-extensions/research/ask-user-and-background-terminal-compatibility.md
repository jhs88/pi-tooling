# Ask User and background-terminal compatibility

**Decision:** proceed with clean-room implementations of `ask_user` and session-scoped background terminals, but do not transplant the Ben Davis source. `ask_user` is compatible with Pi/TUI 0.80.10 and is a deliberate *narrowing*, not a drop-in rename of the current `questionnaire`. The background-terminal design is also API-compatible, but its shell policy, child-tool denylist, completion delivery, crash cleanup, Windows tree-kill verification, and log/security policy need to be made explicit before implementation.

**Research date:** 2026-07-24 (UTC)
**Source boundary:** primary local source only. Ben Davis snapshot `797eaf6d6f178759cf7aabde927ef15c91346e7e` has no license file, so the material below records observable contracts and compatibility findings for an independent implementation; it does not authorize copying source. Pi source is pinned at `8dc78834cde4e329284cf505f9e3f99763df5529` (package version 0.80.10).

## 3. Background-terminal behavioral contract

### Tools and `/ps`

The observable tool set is `bg_start`, `bg_status`, `bg_list`, and `bg_kill`. `bg_start` returns immediately; the registry allows at most **8 running** terminals and retains at most **32 current snapshots**, pruning oldest settled entries but never running ones. [[tool registration](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/index.ts#L204-L358), [limits/pruning](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L38-L54), local `<upstream-checkout>/extensions/background-terminals/src/manager.ts:333-350,508-527`] The reservation happens before spawning, so parallel starts cannot race through the limit. [local manager `:508-527,699-710`]

`/ps` is a TUI-only, two-stage full-screen overlay: a live list (select/inspect/`x` kill) and a read-only detail view (stdout/stderr toggle, live tail, scroll, top/bottom, kill). It deliberately has no input surface. In non-TUI modes the command emits a textual list only when dialog UI exists; otherwise it is a no-op. [[UI contract](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/ui/ps.ts#L1-L8), [command guard](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/index.ts#L419-L446), local same paths/lines]

### Shell and stdin

- POSIX commands run under fixed `/bin/sh -c`; Windows uses `ComSpec` (fallback `cmd.exe`) with `/d /s /c`. The process inherits `process.env`. stdin is `ignore`, so readers receive EOF immediately; there is no later write API. [[spawn contract](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L169-L175), [spawn options](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L529-L541), local same paths/lines]
- The local `zsh-user-bash.ts` intercepts only Pi's `user_bash` event and invokes zsh `-fc`; Pi documents that event as the user's `!`/`!!` path. [local `<pi-config>/agent/extensions/zsh-user-bash.ts:11-37`; `<pi-source-checkout>/packages/coding-agent/src/core/extensions/types.ts:799-808`] It therefore does **not** affect either model `bash` or `bg_start`.
- Recommendation: keep background shell selection explicit and deterministic. If zsh parity is desired, add an explicit background-shell setting (possibly honoring `PI_USER_BASH_SHELL`) and test it; do not source interactive `.zshrc`, and do not imply that the existing `user_bash` hook applies.

### Process-tree termination

On POSIX, the child is detached into its own process group and termination targets `-pid`: SIGTERM, a 2 s wait, then SIGKILL, followed by a bounded close/settle path. On Windows, termination launches `taskkill /pid PID /T`, adds `/F` for escalation, and falls back to `child.kill`. [[tree kill](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L177-L226), [escalation](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L241-L268), local same paths/lines]

A cancelled `bg_kill` stops waiting but leaves detached termination running, which is the correct user-visible contract. [local `<upstream-checkout>/extensions/background-terminals/index.ts:321-344`; manager `:727-800`] POSIX group/tree and SIGKILL escalation have source tests; those tests are explicitly skipped on Windows. [local `<upstream-checkout>/extensions/background-terminals/manager.test.ts:187-223,274-333`] Therefore Windows **compatibility is plausible but not established** until a Windows CI/integration test proves descendants die and no process remains after the bounded shutdown.

### Output, spill, retention, and secrets

- stdout and stderr are separate. Memory retains the newest **2 MiB per stream** with UTF-8-safe head eviction; every raw chunk is also offered to an unbounded full spill file. [[buffer](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/output.ts#L1-L9), [cap](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L38-L53), local same paths/lines]
- `bg_status` returns tails bounded to 16 KiB/400 lines stdout and 8 KiB/200 lines stderr. Completion follow-ups are smaller: 8 KiB/40 lines and 4 KiB/20 lines. Pi's shared maximum is 50 KiB/2,000 lines. [[background caps](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/prompt.ts#L12-L23), [Pi caps](https://github.com/earendil-works/pi/blob/8dc78834cde4e329284cf505f9e3f99763df5529/packages/coding-agent/src/core/tools/truncate.ts#L1-L13), local same paths/lines]
- Spill storage is a per-extension-session directory below `${tmpdir}/pi-background-terminals/session-*`, mode 0700, with stream files mode 0600. The whole directory is removed on normal runtime disposal. [[spill creation](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L454-L505), [disposal](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/src/manager.ts#L802-L828), local same paths/lines]
- The `/ps` detail view reads only the 2 MiB retained buffer and points at the spill path after head truncation; it does **not** read the full spill file. [local `<upstream-checkout>/extensions/background-terminals/src/ui/ps.ts:548-576`] Any wording that says the full log is “in `/ps`” is inaccurate. If spilling fails and the buffer truncates, the dropped output is unrecoverable despite the current fallback text “Full output in the /ps viewer.” [local `<upstream-checkout>/extensions/background-terminals/src/prompt.ts:85-105`]

**Security decision:** do not ship unbounded, unredacted capture as-is. A command inherits all Pi environment variables and can print credentials; raw output is then (1) stored in `/tmp`, (2) partially injected into model context and provider requests, (3) rendered in the transcript, and (4) referenced by an absolute spill path. Display-time ANSI sanitization is not secret redaction. Normal shutdown deletes spill files, but transcript/model copies remain, and a hard crash can leave the temporary directory indefinitely because there is no TTL/startup scavenger. The clean implementation needs a per-stream/per-session disk quota, startup stale-directory cleanup, best-effort redaction before model delivery, explicit “logs may contain secrets” guidance, and accurate degradation when spill creation/flush fails. Keep directory/file modes 0700/0600.

## 4. Completion follow-up and `notify.ts`

Natural process settlement is deferred and delivered as a custom message with `{ deliverAs: "followUp", triggerTurn: true }`. If the parent is idle it starts a turn; if streaming it queues behind the current work. A settled `bg_status` or active `bg_kill` consumes the pending settlement to avoid duplicate model delivery, while a `/ps`-initiated kill intentionally still produces a follow-up. [[delivery](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/background-terminals/index.ts#L119-L179), local same path/lines; `<upstream-checkout>/extensions/background-terminals/src/result-delivery.ts:1-27`]

Pi 0.80.10 supports exactly this queueing contract: while streaming, `followUp` enters the follow-up queue; while idle, `triggerTurn` starts a run. [[Pi implementation](https://github.com/earendil-works/pi/blob/8dc78834cde4e329284cf505f9e3f99763df5529/packages/coding-agent/src/core/agent-session.ts#L1405-L1450), local same path/lines] Pi processes queued follow-ups before `agent_end`, so the local `notify.ts` notification normally fires after the model has handled completion, not at raw process exit. [local `<pi-source-checkout>/packages/agent/src/agent-loop.ts:262-275`; `<pi-config>/agent/extensions/notify.ts:51-54`]

Two caveats must be fixed or tested:

1. `pi.sendMessage` is typed `void`; its runtime starts asynchronous delivery and reports later failure through the extension error channel. [local `<pi-source-checkout>/packages/coding-agent/src/core/extensions/types.ts:1266-1270`; `<pi-source-checkout>/packages/coding-agent/src/core/agent-session.ts:2337-2346`] The reviewed implementation's synchronous `try/catch` and “retry on failure” cannot detect that later rejection. Treat completion delivery as best-effort unless the clean implementation adds an acknowledged delivery seam.
2. Each idle settlement-triggered model run ends in `agent_end`, so `notify.ts` emits “Ready for input” for that run. This is useful, but multiple separately settling jobs can generate multiple notifications. Keep completion messages coalescible and test the local `followUpMode: one-at-a-time` behavior; consider moving readiness notification to `agent_settled` if early/intermediate notifications are observed.

## 5. Session shutdown: guarantee and boundary

Pi 0.80.10 awaits `session_shutdown` before invalidating an extension runtime on new/resume/fork and on dispose; reload also awaits it. [[runtime teardown](https://github.com/earendil-works/pi/blob/8dc78834cde4e329284cf505f9e3f99763df5529/packages/coding-agent/src/core/agent-session-runtime.ts#L167-L175), [dispose](https://github.com/earendil-works/pi/blob/8dc78834cde4e329284cf505f9e3f99763df5529/packages/coding-agent/src/core/agent-session-runtime.ts#L395-L402), local same paths/lines; `<pi-source-checkout>/packages/coding-agent/src/core/agent-session.ts:2577-2588`] The background extension clears UI/delivery state and awaits runtime disposal; disposal closes all entry scopes concurrently, bounds each close, waits cleanup fibers, and deletes spills. [local `<upstream-checkout>/extensions/background-terminals/index.ts:181-202`; manager `:802-828`]

This guarantees cleanup for **normal Pi transitions, reload, quit, SIGTERM, and SIGHUP paths that reach runtime disposal**. It cannot guarantee cleanup after SIGKILL, host/power loss, or every emergency crash. Pi's emergency exit only kills children registered in its internal detached-child tracker, whereas the reviewed manager uses raw `spawn` and does not register there. [local `<pi-source-checkout>/packages/coding-agent/src/modes/interactive/interactive-mode.ts:3525-3559`; `<pi-source-checkout>/packages/coding-agent/src/utils/shell.ts:176-225`; reviewed manager `:529-541`] A clean implementation should add its own idempotent process-exit safety net and stale-spill scavenger, while documenting that SIGKILL/power-loss cleanup is impossible to guarantee.

## 6. Child workflow/subagent policy

Headless in-process children must not receive tools that require the parent user/UI or create isolated session-local background state. Exclude at least:

- `ask_user` and, while it remains installed, `questionnaire`;
- `bg_start`, `bg_status`, `bg_list`, and `bg_kill`;
- existing recursive orchestration tools (`subagent_spawn`, `subagent_wait`, `subagent_cancel`, `subagent_check`, `subagent_list`, `workflow`).

The Ben child policy already excludes recursive orchestration and `ask_user`, but not the four background tools. [[current Ben policy](https://github.com/davis7dotsh/my-pi-setup/blob/797eaf6d6f178759cf7aabde927ef15c91346e7e/extensions/shared/child-session.ts#L11-L27), local same path/lines; `<upstream-checkout>/extensions/subagents/src/backends/pi.ts:42-51,340-360`] A child has its own extension instance/registry, so its `bg_status`/`bg_kill` cannot manage the parent's jobs; a child `bg_start` job is killed as soon as the child session shuts down and its automatic follow-up has no useful parent destination. Excluding all four avoids misleading and leak-prone behavior. Apply the same denylist to workflow-created Pi sessions.

## 7. Independent implementation seams

Implement behavior from this report, not source structure:

1. **Ask contract (pure):** schema validation, outcome algebra (`selected`, `custom`, `dismissed`, `aborted`, `no-ui`), and model-visible formatter.
2. **Ask TUI adapter:** one-question component with explicit signal/dispose ownership; no dependency on questionnaire state or batch tabs.
3. **Process adapter:** platform shell selection, no-stdin spawn, process-group/tree terminate, and an injectable clock/spawn/taskkill interface.
4. **Terminal supervisor:** atomic 8-slot reservation, registry/state transitions, idempotent settlement, 32-entry pruning, and shutdown barrier.
5. **Output store:** independent bounded UTF-8 tail plus quota-bounded private spill, flush acknowledgement, stale cleanup, and redaction policy.
6. **Completion broker:** keyed exactly-once-within-process consumption/coalescing, with an explicit acknowledged send adapter instead of assuming `pi.sendMessage` throws synchronously.
7. **Presentation:** model result formatting, renderer sanitization, widget, and `/ps` read model separated from process ownership. `/ps` should either page the spill file or honestly label itself a retained-tail viewer.
8. **Extension wiring:** one lifecycle composition root that owns hooks, tool registration, child exclusions, and final disposal.

These seams permit unit testing without running Pi and keep the unlicensed snapshot out of the implementation.

### Verification performed during research

No Pi, OpenCode, or local inference process was run, and `<pi-config>` was not modified. Source/API compatibility was checked against the pinned trees. The snapshot had no installed `node_modules`: `npm run check` could not start because `tsc` was absent, and the background test command reported 14 passing dependency-free tests plus three module-load failures (`effect` / host Pi packages missing). This is **not** a passing suite and is why dependency installation plus the matrix above remains an implementation gate.
