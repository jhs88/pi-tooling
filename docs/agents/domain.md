# Domain docs

This repository uses a single domain context.

## Before exploring the code

Read the root [GLOSSARY.md](../../GLOSSARY.md) and the [ADRs](../adr/README.md) relevant to the area you are changing. If a domain document is absent, proceed without creating a placeholder.

## Use the glossary's vocabulary

Use the glossary's terms in issue titles, proposals, explanations, and test names. Follow its preferred terms and avoid the listed synonyms. Resolve new domain terms with `/domain-modeling` when needed.

## Record decisions

Surface conflicts with existing ADRs before changing the architecture. Create an ADR when a decision is hard to reverse, surprising without context, and the result of a real trade-off. Keep task state and implementation checklists in [GitHub Issues](issue-tracker.md).
